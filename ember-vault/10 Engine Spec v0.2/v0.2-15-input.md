# 15 — Input: v0.2 delta

Changes against [[15-input]]. Index: [[v0.2 Spec Index]].

## 1. Action map

Round V1.3, [[v0.2-50-design-decisions#ADR-052: Input action map|ADR-052]].
Implements [[15-input]] §2.2 and §5, with the changes below; replaces
§6 (analog actions and dead zones) until gamepad axes exist.

```rust
// ember_input
pub struct ActionMap {
    pub swipe_distance: f32,   // default 32.0, viewport (canvas) units
    pub mouse_swipe: bool,     // default false
    pub actions: Vec<Action>,
}
pub struct Action {
    pub name: String,
    pub keys: Vec<Key>,
    pub gamepad: Vec<GamepadButton>,
    pub mouse: Vec<MouseButton>,
    pub swipe: Vec<Swipe>,
}
pub enum Swipe { Left, Right, Up, Down }        // #[non_exhaustive]

impl ActionMap {
    pub fn from_ron(text: &str) -> Result<Self, ActionMapError>;
    pub fn to_ron(&self) -> String;
    pub fn validate(&self) -> Result<(), ActionMapError>;
    pub fn get(&self, name: &str) -> Option<&Action>;
    pub fn with_key(self, name: &str, key: Key) -> Self;   // + with_gamepad / with_mouse / with_swipe
}

pub struct ActionResolver { /* map + state across frames */ }
impl ActionResolver {
    pub fn new(map: ActionMap) -> Self;
    pub fn resolve(&mut self, input: &mut Input);   // fills input.actions
}

pub struct Input { /* v0.1 fields */ pub actions: ActionState }
impl Input {
    pub fn action(&self, name: &str) -> bool;             // down
    pub fn action_pressed(&self, name: &str) -> bool;
    pub fn action_released(&self, name: &str) -> bool;
    pub fn action_axis(&self, negative: &str, positive: &str) -> f32;  // -1, 0, +1
    pub fn action_vector(&self, left: &str, right: &str, up: &str, down: &str) -> Vec2;
    pub fn swipe(&self) -> Option<Swipe>;
}

// ember_scene
impl SceneLoop {
    pub fn with_action_map(self, map: ActionMap) -> Self;
    pub fn set_action_map(&mut self, map: Option<ActionMap>);
    pub fn action_map(&self) -> Option<&ActionMap>;
}
```

### 1.1 File format (replaces §5.1)

```ron
(
    swipe_distance: 32.0,      // optional
    mouse_swipe: false,        // optional
    actions: [
        (name: "move_left",  keys: [A, Left],  gamepad: [DPadLeft],  swipe: [Left]),
        (name: "move_right", keys: [D, Right], gamepad: [DPadRight], swipe: [Right]),
        (name: "undo",       keys: [Z, Backspace], gamepad: [West]),
        (name: "confirm",    keys: [Space, Enter], gamepad: [South], mouse: [Left]),
    ],
)
```

Every list is optional. Names are non-empty and unique. Stick bindings
(`LeftStickLeft`) and `dead_zone` from v0.1 §5.1 / §6.2 do not exist yet.

### 1.2 Rules

- An action is **down** while any of its bindings is down (a key or
  button in `*_down` or `*_pressed`), and on the frame a bound swipe is
  recognised. **pressed** / **released** are edges of *down* across
  frames: a second binding going down while the first is held does not
  press again.
- Result lists in `Input::actions` are in the map's action order.
- A **swipe** is recognised once per stroke: on the first frame the
  finger is `swipe_distance` from where it touched down (or on its
  `Ended` frame, for a quick flick), in the dominant direction (ties go
  horizontal). Cancelled touches and fingers that stop being reported
  never swipe. With `mouse_swipe`, a left-button drag counts the same.
- `action_axis` is `+1` while `positive` is down, `-1` while `negative`
  is, `0` for both or neither. `action_vector` is in screen space
  (`y` grows down) and scales a diagonal to length 1.
- `SceneLoop` resolves after the virtual-resolution mapping, so
  distances are canvas units. `set_action_map` (runtime rebinding,
  §11 Q3) restarts held state. `input_mut()` bypasses the resolver.
- §5.4 *Re-loading*: no asset hot reload; reload by calling
  `set_action_map` with a new map.
- §11 Q2 (chords) stays *no*.
