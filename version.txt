## Vue d'ensemble du projet

Ember est un moteur de jeu 2D en Rust, avec une architecture en 3 couches :

1. ember_core — Primitives pures, aucune dépendance graphique.
2. ember_stdlib — Briques de jeu réutilisables, dépend de macroquad.
3. games/* — Jeux spécifiques, chacun dans son dossier.

Stack technique :
- Langage : Rust, edition 2024 partout.
- Rendu / input / fenêtre : macroquad 0.4 avec feature "audio" activée.
- Math : glam 0.27 (aligné sur macroquad 0.4.16).
- Sérialisation : serde + ron.
- Config : dotenvy (fichiers .env).
- Structure : Cargo workspace avec [workspace.package] (edition, version) et [workspace.dependencies] (versions + chemins internes).
- Resolver : resolver = "3" explicite dans le workspace racine.
- Convention Session 6 : tous les membres utilisent edition.workspace = true, version.workspace = true et dep.workspace = true. [workspace.dependencies] est la source unique de vérité. Bumper une version = éditer un seul fichier (le root). Vérifié par cargo tree -i glam / -i macroquad → une seule version résolue pour tout le workspace.

Conventions clés :
- transform.position = top-left par défaut, sauf :
  - Bullet Hell : position = centre (déviation assumée, documentée dans bullet-hell/src/lib.rs).
- Les jeux sont data-driven via des fichiers .ron.
- Les tests sont obligatoires (unit + intégration).
- La stratégie est "Rule of Three" : on n'extrait dans le moteur qu'après avoir vu le pattern 3 fois.
- Crates externes : tirets dans Cargo.toml (ember-core, bullet-hell), underscores dans le code (ember_core, bullet_hell).
- cargo clippy --workspace --all-targets -- -D warnings est le gate de qualité. Il doit rester vert.
- State structs : chaque jeu expose un unique struct qui possède tout l'état mutable (MatchState, BreakoutWorld, SnakeWorld, GameWorld, World pour Bullet Hell, Game pour Minesweeper, App + GameWorld pour Simon, Game pour Memory, Game pour FreeCell, Game pour Air Hockey, Game pour Zhuo Ji, Game pour ember-wars). main.rs tient une seule variable de ce type. C'est une convention, pas un type partagé.
- **Layout uniforme (Phase 14)** : le state struct vit dans `systems.rs`, `GameContext` vit dans `config.rs`, `lib.rs` fait les réexports. `systems.rs` fait `pub use crate::config::GameContext;` pour compat.
- Séparation BoardState / GameState (Minesweeper) : l'état interne du plateau (Ready/Playing/Won/Lost) est distinct de l'état d'écran (Start/Playing/Win/GameOver). Transitions explicites.
- Boutons UI : update() et draw() doivent être appelés sur la MÊME instance. Si le bouton est recréé dans le rendu, l'event de clic est perdu. Conserver les boutons dans le state struct du jeu.
- .env colors : env_color("PREFIX", default) lit quatre variables séparées PREFIX_R, PREFIX_G, PREFIX_B, PREFIX_A, chacune un f32 dans [0.0, 1.0]. Jamais une chaîne r,g,b,a. Préférer le préfixe COLOR_<ROLE>_.
- draw_text vs draw_centered vs Label::new :
  - draw_text(format!(...), ...) — macroquad accepte impl AsRef<str>, donc PAS de &.
  - draw_centered(&format!(...), ...) — signature prend &str, donc le & est nécessaire.
  - Label::new(format!(...), ...) — prend impl Into<String>, donc PAS de &.
  Règle générale : si la fonction prend impl AsRef<str> ou impl Into<String>, retirer le &. Clippy râle (needless_borrows_for_generic_args) sinon.
- TextDimensions : macroquad::draw_text retourne TextDimensions, pas (). Pour ignorer, terminer par ;.
- manual_range_contains : écrire (a..=b).contains(&x) au lieu de x >= a && x <= b.
- **Design docs (Phase 17)** : chaque nouveau jeu doit avoir un `DESIGN.md` dans son dossier. Premier : `games/memory/DESIGN.md`. À faire rétroactivement pour Pong, Breakout, Snake, Asteroids, Bullet Hell, Minesweeper, Simon.
- **Clavier AZERTY vs QWERTY (Phase 18)** : macroquad utilise les scancodes QWERTY, pas les caractères du layout. Sur AZERTY : `M` → `KeyCode::Semicolon`, `Z` → `KeyCode::W`, `A` ↔ `Q`, `W` ↔ `Z`. Toujours préférer `Tab`, `Escape`, `Space`, `Enter`, ou les touches de fonction pour les raccourcis critiques.
- **`clippy::collapsible_if` (Phase 21)** : let-chains (`if let Some(x) = ... && cond { }`) stables depuis Rust 1.88, à utiliser.
- **`clippy::doc_overindented_list_items` (Phase 21)** : sous-items doc-comment alignés à 2 espaces après le `-`.
- **`clippy::too_many_arguments` (Phase 21)** : bundler en tuple. Ex : `draw_filter_btn(rect: (f32, f32, f32, f32), ...)`.
- **`gen` est un mot réservé en édition 2024 (Phase 23)** : ne jamais l'utiliser comme identifiant. Préférer `id_gen`, `generator`, `rng_state`.
- **`clippy::should_implement_trait` (Phase 23)** : sur une méthode `next()` custom → renommer `next_id()`.
- **`clippy::vec_init_then_push` (Phase 23)** : préférer `vec![...]` à `let mut v = Vec::new(); v.push(...); ...`.
- **`clippy::manual_is_multiple_of` (Phase 23)** : `.is_multiple_of(n)` au lieu de `% n == 0`.
- **`set_default_font` après `load_ttf_font` (Phase 23)** : pattern canonique Ember pour les polices Unicode. Utilisé par FreeCell et ember-wars.

  impl<T> Clone for Persistence<T> { ... }   // manuel, sans bound T: Clone

  impl<T: Serialize + DeserializeOwned> Persistence<T> {

  // Records « higher wins » / « lower wins »

**Important (Phase 16)** : `in_manifest_dir` prend `manifest_dir: &Path` en paramètre, parce que `env!("CARGO_MANIFEST_DIR")` est évalué **là où la macro est écrite** (donc dans la stdlib), pas au point d'appel.

**`update_best_in_map`** (Phase 22) extrait de 3 jeux (Minesweeper, FreeCell, Memory). La clé accepte n'importe quel `ToString` : `&str` (nom de difficulté), `String`, `u32` (seed FreeCell).

## games/ember-wars — Détail (12e jeu)

### Concept

Inspiré de **Cartoon Wars** (Gamevil, 2009) : hybride Tower
Defense / RTS side-scrolling. Deux tours s'affrontent, chaque camp
spawn des unités qui avancent automatiquement, le joueur gère une
ressource (Mana) et vise manuellement avec une tourelle. Objectif :
détruire la tour ennemie OU survivre N secondes selon le niveau.

**Thème visuel** : campagne à deux chapitres, chacun avec une
identité propre.

- **Chapitre 1 : Shanghai** — nuit urbaine, skyline de gratte-ciels
  à fenêtres jaunes, enseignes néon, ciel violet/rose.
- **Chapitre 2 : Guiyang** — aube brumeuse sur les montagnes
  karstiques, pagodes, rizières.

### Détail technique

#### Campagne

- **Chapitre 1 : Shanghai**
  - sh_01 "Les quais" (Survive 45s, 1600px, 400 HP)
  - sh_02 "Le Bund" (Destroy, 1800px, 500 HP, 3 waves)
  - sh_03 "Pudong" (Destroy, 2000px, 600 HP, 5 waves)
- **Chapitre 2 : Guiyang**
  - gy_01 "Les rizières" (Survive 60s, 1700px, 500 HP)
  - gy_02 "La montagne" (Destroy, 1900px, 700 HP, 4 waves)
  - gy_03 "La citadelle" (Destroy, 2100px, 800 HP, 5 waves)

Chapitres débloqués séquentiellement (tous les niveaux du précédent
à ≥1⭐).

#### Unités (6)

| Unité | Coût | Rôle | Débloqué par |
|---|---|---|---|
| Grunt | 15 | Melee basique | Défaut |
| Brute | 40 | Melee lourd, tank | Défaut |
| Archer | 30 | Ranged (projectile) | Arbre (`unlock_archer`) |
| Healer | 45 | Soigne allié le plus blessé | Arbre (`unlock_healer`) |
| Bomber | 35 | Suicide AoE (70px) | Arbre (`unlock_bomber`) |
| Hero | 90 | Melee fort, max 1 vivant | Arbre (`unlock_hero`) |

#### Upgrade Tree (18 nœuds, 4 branches)

- **Défense** (col -3) : Tower HP I/II, Regen, Fortress.
- **Armée** (col -1) : Unit HP I/II, Unlock Archer/Healer/Bomber/Hero.
- **Tourelle** (col +1) : Turret Dmg I/II, Fire Rate, Multi-shot.
- **Économie** (col +3) : Mana Regen, Gold per kill, Mana Cap.

**Effets** : `TowerHpMult`, `TowerRegen`, `Fortress`, `UnitHpMult`,
`UnitDamageMult`, `UnlockUnit(String)`, `TurretDamageMult`,
`TurretFireRateMult`, `MultiShot(u32)`, `ManaRegenMult`,
`ManaCapMult`, `GoldPerKillAdd`.

**Validation** au chargement : ids uniques, requires existants,
exactement 1 racine, pas de cycle (Kahn).

**Agrégation** : les mults se multiplient, les additifs s'additionnent.

Achetés dans le **menu** via `Tab`. **Persistés** dans `progress.ron`
(avec la bank d'or).

#### Progression

- **Étoiles** : 1⭐ win, 2⭐ tower HP ≥ 50%, 3⭐ tower HP ≥ 90%.
- **Or persistant** : crédité à la fin du niveau.
- **Chapitres verrouillés** : débloqués par complétion du précédent.
- `progress.ron` **gitignoré**.

#### Décor procédural

Aucun asset externe. Tout est dessiné en code avec
`textures.rs` :

- **`draw_sky`** — dégradé vertical en strips + étoiles (Urban).
- **`draw_far_layer`** — skyline lointaine ou montagnes, parallax 0.25.
- **`draw_mid_layer`** — skyline proche ou collines + pagodes,
  parallax 0.55, fenêtres + néons (Urban).
- **`draw_ground`** — sol + pavés / herbe + néons au sol (Urban).
- **`draw_mist`** — bande de brume (Mountain).
- **`draw_tower`** — tour stylisée avec fenêtres, créneaux, porte,
  antenne + voyant.

**Hash déterministe** : `hash_u32(seed, x)` (murmur-inspired).
Générateurs : `far_urban_height`, `mid_urban_height`,
`far_mountain_height`, `mid_mountain_height`.

**Palettes** dans `palettes.ron`. **Seed** par niveau
(`visual_seed` dérivé du game seed).

#### Juice

- **Hit flash** blanc 80ms sur les unités touchées.
- **Particles** de mort (6 par kill, 10 pour bomber).
- **Screen shake** proportionnel aux dégâts sur les tours.
- **Floating numbers** "-X" cyan sur les hits de tourelle.
- **Flash** doré à chaque achat d'upgrade.
- **Flash** coloré (vert/rouge) à la fin de niveau.

#### Police

**DejaVu Sans Mono** chargée via `set_default_font`. Résout les
étoiles ★☆ et les accents.

#### Sol responsive

`ground_y_for(viewport_h) = viewport_h - SPAWN_BAR_H - BOTTOM_MARGIN - GROUND_PADDING`.
Recalculé à chaque frame via `Game::update_viewport`. Les unités
existantes sont décalées en Y si le sol bouge.

#### Contrôles

- **Menu** :
  - Clic sur niveau débloqué → lance la partie.
  - Molette / ↑↓ → scroll.
  - Tab → modal Upgrade Tree.
  - Échap → quitter.
- **En jeu** :
  - ← / → : scroll caméra.
  - Clic gauche sur la map : tir de tourelle.
  - Clic gauche sur la barre de spawn : spawn unité.
  - 1 / 2 / 3 : type de tir (Basic / Piercing / Explosive).
  - R : retry.
  - Échap : retour menu.
  - Entrée : retour menu après fin.
