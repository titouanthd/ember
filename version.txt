## Vue d'ensemble du projet

Ember est un moteur de jeu 2D en Rust, avec une architecture en 3 couches :

1. ember_core — Primitives pures, aucune dépendance graphique.
2. ember_stdlib — Briques de jeu réutilisables, dépend de macroquad.
3. games/* — Jeux spécifiques, chacun dans son dossier.

Stack technique :
- Langage : Rust, edition 2024 partout.
- Rendu / input / fenêtre : macroquad 0.4 avec feature "audio" activée.
- Math : glam 0.27 (aligné sur macroquad 0.4.16).
- Sérialisation : serde + ron.
- Config : dotenvy (fichiers .env).
- Structure : Cargo workspace avec [workspace.package] (edition, version) et [workspace.dependencies] (versions + chemins internes).
- Resolver : resolver = "3" explicite dans le workspace racine.
- Convention Session 6 : tous les membres utilisent edition.workspace = true, version.workspace = true et dep.workspace = true. [workspace.dependencies] est la source unique de vérité. Bumper une version = éditer un seul fichier (le root). Vérifié par cargo tree -i glam / -i macroquad → une seule version résolue pour tout le workspace.

Conventions clés :
- transform.position = top-left par défaut, sauf :
  - Bullet Hell : position = centre (déviation assumée, documentée dans bullet-hell/src/lib.rs).
- Les jeux sont data-driven via des fichiers .ron.
- Les tests sont obligatoires (unit + intégration).
- La stratégie est "Rule of Three" : on n'extrait dans le moteur qu'après avoir vu le pattern 3 fois.
- Crates externes : tirets dans Cargo.toml (ember-core, bullet-hell), underscores dans le code (ember_core, bullet_hell).
- cargo clippy --workspace --all-targets -- -D warnings est le gate de qualité. Il doit rester vert.
- State structs : chaque jeu expose un unique struct qui possède tout l'état mutable (MatchState, BreakoutWorld, SnakeWorld, GameWorld, World pour Bullet Hell, Game pour Minesweeper, App + GameWorld pour Simon, Game pour Memory, Game pour FreeCell, Game pour Air Hockey). main.rs tient une seule variable de ce type. C'est une convention, pas un type partagé.
- **Layout uniforme (Phase 14)** : le state struct vit dans `systems.rs`, `GameContext` vit dans `config.rs`, `lib.rs` fait les réexports. `systems.rs` fait `pub use crate::config::GameContext;` pour compat.
- Séparation BoardState / GameState (Minesweeper) : l'état interne du plateau (Ready/Playing/Won/Lost) est distinct de l'état d'écran (Start/Playing/Win/GameOver). Transitions explicites.
- Boutons UI : update() et draw() doivent être appelés sur la MÊME instance. Si le bouton est recréé dans le rendu, l'event de clic est perdu. Conserver les boutons dans le state struct du jeu.
- .env colors : env_color("PREFIX", default) lit quatre variables séparées PREFIX_R, PREFIX_G, PREFIX_B, PREFIX_A, chacune un f32 dans [0.0, 1.0]. Jamais une chaîne r,g,b,a. Préférer le préfixe COLOR_<ROLE>_.
- draw_text vs draw_centered vs Label::new :
  - draw_text(format!(...), ...) — macroquad accepte impl AsRef<str>, donc PAS de &.
  - draw_centered(&format!(...), ...) — signature prend &str, donc le & est nécessaire.
  - Label::new(format!(...), ...) — prend impl Into<String>, donc PAS de &.
  Règle générale : si la fonction prend impl AsRef<str> ou impl Into<String>, retirer le &. Clippy râle (needless_borrows_for_generic_args) sinon.
- TextDimensions : macroquad::draw_text retourne TextDimensions, pas (). Pour ignorer, terminer par ;.
- manual_range_contains : écrire (a..=b).contains(&x) au lieu de x >= a && x <= b.
- **Design docs (Phase 17)** : chaque nouveau jeu doit avoir un `DESIGN.md` dans son dossier. Le premier est `games/memory/DESIGN.md`. À faire rétroactivement pour les 8 autres jeux.
- **Clavier AZERTY vs QWERTY (Phase 18)** : macroquad utilise les scancodes QWERTY, pas les caractères du layout. Sur AZERTY : `M` → `KeyCode::Semicolon`, `Z` → `KeyCode::W`, `A` ↔ `Q`, `W` ↔ `Z`. Toujours préférer `Tab`, `Escape`, `Space`, `Enter`, ou les touches de fonction pour les raccourcis critiques. Solution FreeCell : `Tab` pour le menu, `Z`/`W` pour undo (double mapping), `Y` pour redo (position identique).

## games/freecell — Détail (9e jeu)

### Concept

FreeCell, le solitaire à information parfaite (1978, Paul Alfille). Un
jeu de 52 cartes, toutes visibles dès le départ. Pas de pioche, pas de
hasard pendant la partie. Le joueur déplace des cartes entre 8 colonnes
du tableau, 4 cellules libres (en haut à gauche), et 4 fondations
(en haut à droite).

Objectif : déplacer toutes les cartes vers les fondations, par couleur
et dans l'ordre croissant (A → 2 → ... → K).

Thème visuel : terminal dev (fond sombre, symboles Unicode ♠ ♥ ♦ ♣).

│   ├── deck.rs                # création, distribution, seed
│   ├── drag.rs                # DragState, machine à états
│   ├── font.rs                # chargement DejaVu Sans Mono
│   ├── layout.rs              # positions des colonnes/cellules/fondations
│   ├── persistence.rs         # façade BestTimes
│   └── systems.rs             # Game, rules, super-move, undo/redo, hint
└── tests/
    └── game_scenarios.rs      # 8 tests d'intégration

### Détail technique

- **Cartes** : `Card { suit: Suit, rank: Rank }`, `Rank(pub u8)` avec 1=As, 11=Valet, 12=Dame, 13=Roi.
- **Zones** : `Zone::Column(0..8)`, `Zone::FreeCell(0..4)`, `Zone::Foundation(0..4)`.
- **Distribution** : 4 colonnes de 7 cartes + 4 colonnes de 6 cartes = 52. Déterministe depuis une seed via `Rng` + Fisher-Yates.
- **Règles** : `can_place_on_column`, `can_place_on_foundation`, `can_place_in_cell`, `max_super_move`.
- **Super-move** : formule `(1 + cellules_libres) × 2^colonnes_vides`. **Piège** : si on dépose sur une colonne **vide**, elle ne compte pas comme buffer temporaire disponible (elle est occupée par le move lui-même).
- **Accessibilité** : on ne peut prendre que le **run contigu du bas** d'une colonne. `is_accessible(from, start_idx, n)` vérifie `start_idx + n == columns[col].len()`.
- **Drag-and-drop** : `DragState::Idle / Pressing { origin, card, press_pos } / Dragging { origin, start_index, cards, offset }`. Seuil de 5 px pour passer de Pressing à Dragging.
- **Hit testing** : `hit_test(mouse)` retourne `(Zone, index)`. Parcourt cellules → fondations → colonnes, en cherchant la carte la plus basse dans chaque colonne.
- **Undo/redo** : snapshots complets de l'état (colonnes + cellules + fondations + moves). Pile `history` / `future`. Nouveau move = `future.clear()`.
- **Hint** : `find_hint()` retourne `Hint { from, to, card }` sans muter l'état. Priorité : fondation > colonne > cellule libre.
- **Best time** : `Persistence<HashMap<String, f32>>`, clé = seed stringifiée.
- **Police** : DejaVu Sans Mono chargée au démarrage pour les symboles Unicode ♠ ♥ ♦ ♣. Fallback ASCII S/H/D/C documenté.
- **Raccourcis clavier** (cross-layout) : `N` new, `R` restart, `Tab` menu, `Z`/`W` undo, `Y` redo, `Escape` quit.
- **Tests** : 81 unitaires + 8 intégration = **89 tests**.

### Pièges connus

- **Unicode rendering** : macroquad's default font (ProggyClean.ttf) ne couvre que l'ASCII de base. Les symboles ♠ ♥ ♦ ♣ (U+2660..U+2667) ne rendent pas (tofu □). Charger DejaVu Sans Mono via `load_ttf_font` + `set_default_font`.
- **Clavier AZERTY** : `KeyCode::M` correspond au scancode QWERTY, donc sur AZERTY la touche `M` physique envoie `KeyCode::Semicolon`. Idem pour `Z` ↔ `W`, `A` ↔ `Q`. Solution : utiliser `Tab` (position identique) ou mapper plusieurs KeyCode.
- **Fondations noires invisibles** : sur fond sombre, un symbole noir en alpha 0.20 est invisible. Utiliser une couleur claire (gris) + alpha ≥ 0.45 pour les placeholders.
- **Timer et boutons** : le timer positionné en dur à `window_w - 380` peut chevaucher les boutons. Calculer sa position depuis `hint_btn.rect.0` (coin gauche du bouton).
- **Dernière carte de colonne** : si `card_stack_offset` est trop grand, les longues colonnes débordent du footer. 30 px minimum, 35-40 px recommandé.
- **`can_drop_at` et `max_super_move`** : la formule dépend de la **destination**. Déposer 3 cartes sur une colonne vide avec 0 cellule libre → la colonne vide ne compte pas comme buffer → limite = 1. Source classique de confusion pour le joueur (prévoir un affichage « Max: X » dans le HUD en V2).

## games/air-hockey — Détail (10e jeu)

### Concept

Air Hockey, arcade 2 joueurs (ou 1 joueur vs IA). Table horizontale,
deux palets contrôlés par W/A/S/D (J1) et flèches (J2), un palet
unique. Objectif : 3 buts par manche, 2 manches gagnantes sur 3.

### Structure

games/air-hockey/
├── Cargo.toml
├── .env                       # couleurs + tuning (goals_to_win_round=3)
├── DESIGN.md                  # à créer (rétroactif)
├── assets/
│   └── DejaVuSansMono.ttf
├── src/
│   ├── main.rs                # boucle, input, rendu, overlays
│   ├── lib.rs
│   ├── config.rs              # GameContext, Tuning, Colors
│   ├── components.rs          # Paddle, Puck, Trail, Particle, Side
│   ├── arena.rs               # géométrie (goal_h, wall, half_for)
│   ├── physics.rs             # substep loop, collisions, goal detection
│   ├── systems.rs             # Game, Phase, GameMode, GameEvent
│   ├── ai.rs                  # AiState + direction (goalkeeper)
│   ├── effects.rs             # Shake, Hitstop, Particles
│   ├── audio.rs               # SoundBank
│   └── font.rs                # DejaVu Sans Mono
└── tests/
    └── game_scenarios.rs      # 10 tests d'intégration

### Détail technique

- **Phases** : Menu → Countdown → Playing → GoalPause → (Countdown | RoundOver | MatchOver).
- **Physique** : `step_world_substepped` avec `substeps = 4`. Le palet est
  clampé à `puck_speed_max = 1400`. Détection de but avant résolution
  des murs pour éviter le tunneling.
- **Hitstop** : `dt_eff = 0.0` quand le palet tape un palet à plus de
  900 px/s. IMPORTANT : ne pas appeler `step_world_substepped` quand
  `dt_eff == 0.0`, sinon boucle infinie (le palet coincé entre deux
  palets re-trigger hitstop à chaque frame).
- **IA goalkeeper** : `REACTION_TIME = 0.18s`, `AI_SPEED = 0.55`,
  `GOALIE_OFFSET = 70.0`. Reste sur sa ligne x, suit le y perçu
  (avec délai), revient au centre si le palet est derrière. Ne chasse
  jamais en x (sinon il pousse le palet dans son propre but).
- **Menu** : Space = PvP, Enter = PvAI. `GameMode` dérivé `Default` = Pvp.
- **Countdown** : `TextParams { font_size: 120, font_scale: 1.4→1.0 }`.
  Ne JAMAIS animer `font_size` (thrash de l'atlas de glyphes, drop FPS).
- **Overlays** : scrim noir alpha 0.55 par-dessus la table quand une
  phase affiche du texte plein écran.
- **Tests** : 58 unitaires + 10 intégration = 68 tests.

### Pièges connus

- **Hitstop infini** : si `dt_eff == 0`, ne pas appeler le step physique.
  Le puck coincé entre deux paddles re-trigger hitstop à l'infini.
- **Countdown font_size animé** : chaque nouvelle taille rastérise de
  nouveaux glyphes dans l'atlas. Animer `font_scale` au lieu de `font_size`.
- **Countdown et le "1" manquant** : `if n > 1 { n } else { "GO!" }`
  écrase le slot du 1. Utiliser une fenêtre `GO_WINDOW` dédiée.
- **Overlays illisibles** : la grille de fond a assez de contraste pour
  noyer le texte. Scrim noir alpha 0.55 minimum.
- **AZERTY pour les contrôles J1** : `W` et `Z` mappés tous les deux sur
  "haut" (positions QWERTY voisines). Idem `A`/`Q` pour gauche. Documenté
  dans `systems.rs`.
