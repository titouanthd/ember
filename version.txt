## Vue d'ensemble du projet

Ember est un moteur de jeu 2D en Rust, avec une architecture en 3 couches :

1. ember_core — Primitives pures, aucune dépendance graphique.
2. ember_stdlib — Briques de jeu réutilisables, dépend de macroquad.
3. games/* — Jeux spécifiques, chacun dans son dossier.

Stack technique :
- Langage : Rust, edition 2024 partout.
- Rendu / input / fenêtre : macroquad 0.4 avec feature "audio" activée.
- Math : glam 0.27 (aligné sur macroquad 0.4.16).
- Sérialisation : serde + ron.
- Config : dotenvy (fichiers .env).
- Structure : Cargo workspace avec [workspace.package] (edition, version) et [workspace.dependencies] (versions + chemins internes).
- Resolver : resolver = "3" explicite dans le workspace racine.
- Convention Session 6 : tous les membres utilisent edition.workspace = true, version.workspace = true et dep.workspace = true. [workspace.dependencies] est la source unique de vérité. Bumper une version = éditer un seul fichier (le root). Vérifié par cargo tree -i glam / -i macroquad → une seule version résolue pour tout le workspace.

Conventions clés :
- transform.position = top-left par défaut, sauf :
  - Bullet Hell : position = centre (déviation assumée, documentée dans bullet-hell/src/lib.rs).
- Les jeux sont data-driven via des fichiers .ron.
- Les tests sont obligatoires (unit + intégration).
- La stratégie est "Rule of Three" : on n'extrait dans le moteur qu'après avoir vu le pattern 3 fois.
- Crates externes : tirets dans Cargo.toml (ember-core, bullet-hell), underscores dans le code (ember_core, bullet_hell).
- cargo clippy --workspace --all-targets -- -D warnings est le gate de qualité. Il doit rester vert.
- State structs : chaque jeu expose un unique struct qui possède tout l'état mutable (MatchState, SnakeWorld, GameWorld, World pour Bullet Hell, Game pour Minesweeper, App + GameWorld pour Simon). main.rs tient une seule variable de ce type. C'est une convention, pas un type partagé.
- Séparation BoardState / GameState (Minesweeper) : l'état interne du plateau (Ready/Playing/Won/Lost) est distinct de l'état d'écran (Start/Playing/Win/GameOver). Transitions explicites.
- Boutons UI : update() et draw() doivent être appelés sur la MÊME instance. Si le bouton est recréé dans le rendu, l'event de clic est perdu. Conserver les boutons dans le state struct du jeu.
- .env colors : env_color("PREFIX", default) lit quatre variables séparées PREFIX_R, PREFIX_G, PREFIX_B, PREFIX_A, chacune un f32 dans [0.0, 1.0]. Jamais une chaîne r,g,b,a. Préférer le préfixe COLOR_<ROLE>_.
- draw_text vs draw_centered vs Label::new :
  - draw_text(format!(...), ...) — macroquad accepte impl AsRef<str>, donc PAS de &.
  - draw_centered(&format!(...), ...) — signature prend &str, donc le & est nécessaire.
  - Label::new(format!(...), ...) — prend impl Into<String>, donc PAS de &.
  Règle générale : si la fonction prend impl AsRef<str> ou impl Into<String>, retirer le &. Clippy râle (needless_borrows_for_generic_args) sinon.
- TextDimensions : macroquad::draw_text retourne TextDimensions, pas (). Pour ignorer, terminer par ;.
- manual_range_contains : écrire (a..=b).contains(&x) au lieu de x >= a && x <= b.

Crate pur : aucune dépendance graphique (audit Session 7, macroquad et slotmap retirés).

Constructeurs : from_corners, from_center_half, from_top_left_size.
Méthodes : center, size, half_size, width, height, contains, contains_strict, overlaps, overlaps_strict, penetration, closest_point, distance_to_point.

### math/circle.rs — Circle

Struct : { center: Vec2, radius: f32 }.

Méthodes : diameter, area, circumference, contains, contains_strict, overlaps, overlaps_aabb, closest_point_on_edge.

Tests : 9.

### time/tick.rs — TickTimer

Accumulateur pour simulations à pas fixe.

  pub fn new(tick_duration: f32) -> Self;
  pub fn set_duration(&mut self, duration: f32);
  pub fn duration(&self) -> f32;
  pub fn advance(&mut self, dt: f32) -> u32;
  pub fn reset(&mut self);
  pub fn progress(&self) -> f32;
  pub fn accumulator(&self) -> f32;

Note importante : TickTimer est un accumulateur de ticks, pas un cooldown booléen. Pour un cooldown "prêt / pas prêt", utiliser un f32 qui décrémente (voir Asteroids, Bullet Hell).

## games/simon — Détail (dernier jeu en date)

### Concept

Simon (jeu de mémoire électronique de 1978). 4 boutons colorés. Le jeu allume une séquence, le joueur la reproduit. Chaque round réussi allonge la séquence. Erreur = game over. Best score persisté.

### Structure

games/simon/
├── Cargo.toml
├── .env                  # COLOR_* en {PREFIX}_R/G/B/A + BUTTON_RADIUS, BUTTON_GAP
├── best_score.ron        # créé au runtime, gitignored
├── sounds/
│   ├── generate_sounds.py   # one-shot, génère les .wav
│   ├── green.wav            # 415 Hz, 400ms, 44.1kHz mono
│   ├── red.wav              # 310 Hz
│   ├── yellow.wav           # 252 Hz
│   └── blue.wav             # 209 Hz
├── src/
│   ├── main.rs           # App struct, boucle, input, rendu
│   ├── lib.rs
│   ├── config.rs         # GameContext
│   ├── components.rs     # SimonColor (Green/Red/Yellow/Blue), button_centers()
│   ├── persistence.rs    # best_score, Path paramétrable (testable)
│   ├── rng.rs            # xorshift32 (3e copie)
│   └── systems.rs        # Sequence, PlayPhase, GameWorld, tick_playback, handle_click
└── tests/                # (pas encore de tests d'intégration)

### Détail technique

- 4 couleurs dans l'ordre historique : Green (haut-gauche), Red (haut-droit), Yellow (bas-gauche), Blue (bas-droit).
- Rendu : CircleButton avec tessellation custom (polygon fan + polyline partageant les vertices).
- Son : joué lors des transitions de couleur allumée, tracké par last_lit: Option<SimonColor> dans App.
- Séquence : Vec<SimonColor>, agrandie de 1 à chaque round via extend_random.
- PlayPhase : PreRound (délai 800ms) → Showing (lit 400ms, gap 200ms par élément) → Waiting (input joueur, pause 300ms après le dernier élément).
- tick_playback BOUCLE jusqu'à épuisement de dt. Sinon, un frame drop > 400ms saute des éléments visuels.
- handle_click valide l'input contre la séquence. Correct / Wrong / RoundComplete / Ignored.
- Best score persisté sur round complete et sur game over.

### Pièges connus

- Audio macroquad : feature "audio" non activée par défaut. Sans elle, tout play_sound imprime un warning et ne joue rien.
- CircleButton tessellation : macroquad draw_circle et draw_circle_lines utilisent des nombres de segments différents, ce qui produit un gap visible entre fill et border. Tesseller manuellement avec circle_segments(radius) qui scale avec le rayon (32 à 128 segments).
- tick_playback : si tu implémentes "une transition par appel", un dt plus grand que le timer de la phase courante saute des états. Boucler avec while remaining > 0.
