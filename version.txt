## Vue d'ensemble du projet

Ember est un moteur de jeu 2D en Rust, avec une architecture en 3 couches :

1. ember_core — Primitives pures, cible : sans dépendance graphique (voir dette).
2. ember_stdlib — Briques de jeu réutilisables, dépend de macroquad.
3. games/* — Jeux spécifiques, chacun dans son dossier.

Stack technique :
- Langage : Rust, edition 2024 partout (y compris Asteroids depuis Session 5).
- Rendu / input / fenêtre : macroquad 0.4.
- Math : glam 0.27 (aligné sur macroquad 0.4.16).
- Sérialisation : serde + ron.
- Config : dotenvy (fichiers .env).
- Structure : Cargo workspace avec [workspace.package] (edition, version) et [workspace.dependencies] (versions + chemins internes).
- Resolver : resolver = "3" explicite dans le workspace racine.
- Convention Session 6 : tous les membres utilisent edition.workspace = true, version.workspace = true et dep.workspace = true. [workspace.dependencies] est la source unique de vérité. Bumper une version = éditer un seul fichier (le root). Vérifié par cargo tree -i glam / -i macroquad → une seule version résolue pour tout le workspace.

Conventions clés :
- transform.position = top-left par défaut, sauf :
  - Bullet Hell : position = centre (déviation assumée, documentée dans bullet-hell/src/lib.rs).
- Les jeux sont data-driven via des fichiers .ron.
- Les tests sont obligatoires (unit + intégration).
- La stratégie est "Rule of Three" : on n'extrait dans le moteur qu'après avoir vu le pattern 3 fois.
- Crates externes : tirets dans Cargo.toml (ember-core, bullet-hell), underscores dans le code (ember_core, bullet_hell).
- cargo clippy --workspace --all-targets -- -D warnings est le gate de qualité. Il doit rester vert.
- State structs : chaque jeu expose un unique struct qui possède tout l'état mutable (MatchState, SnakeWorld, GameWorld, World pour Bullet Hell). main.rs tient une seule variable de ce type. C'est une convention, pas un type partagé — la 3e occurrence (Asteroids GameWorld, Session 5) a confirmé le pattern, elle n'a pas déclenché d'extraction dans le moteur.
- .env colors : env_color("PREFIX", default) lit quatre variables séparées PREFIX_R, PREFIX_G, PREFIX_B, PREFIX_A, chacune un f32 dans [0.0, 1.0]. Jamais une chaîne r,g,b,a. Préférer le préfixe COLOR_<ROLE>_ (Bullet Hell), même si Pong utilise encore PLAYER_COLOR_.
- draw_text vs draw_centered :
  - draw_text(format!(...), ...) — macroquad accepte impl AsRef<str>, donc pas de &.
  - draw_centered(&format!(...), ...) — signature prend &str, donc le & est nécessaire.

## ember_core — Détail

Crate pur : cible = aucune dépendance graphique.
Dette : dépend encore de macroquad (types Color/Rect) et slotmap (futur ECS). Audit à faire : si l'un des deux n'est pas utilisé dans src/, le retirer.

Dépendances (via .workspace = true) : glam, serde, ron, macroquad, slotmap.

### io.rs

Chargement/sauvegarde RON génériques.

  pub fn save_to_file<T: Serialize>(path: &Path, data: &T) -> Result<(), String>;
  pub fn load_from_file<T: DeserializeOwned>(path: &Path) -> Result<T, String>;

Utilisé par : Breakout (niveaux), Snake (niveaux), Bullet Hell (waves.ron), Asteroids (high score).

### math/aabb.rs — Aabb

Struct : { min: Vec2, max: Vec2 }.

Constructeurs : from_corners, from_center_half, from_top_left_size.
Méthodes : center(), size(), half_size(), width(), height(), contains, contains_strict, overlaps, overlaps_strict, penetration, closest_point, distance_to_point.

Tests : 15.

### math/circle.rs — Circle

Struct : { center: Vec2, radius: f32 }.

Méthodes : diameter, area, circumference, contains, contains_strict, overlaps, overlaps_aabb, closest_point_on_edge.

Tests : 9.

### time/tick.rs — TickTimer

Accumulateur pour simulations à pas fixe.

  pub fn new(tick_duration: f32) -> Self;
  pub fn set_duration(&mut self, duration: f32);
  pub fn duration(&self) -> f32;
  pub fn advance(&mut self, dt: f32) -> u32;
  pub fn reset(&mut self);
  pub fn progress(&self) -> f32;
  pub fn accumulator(&self) -> f32;

Note importante : TickTimer est un accumulateur de ticks, pas un cooldown booléen. Pour un cooldown "prêt / pas prêt", utiliser un f32 qui décrémente (voir Asteroids, Bullet Hell).

Tests : 11.

### app/state.rs — GameState

  pub enum GameState { Start, Playing, LevelCleared, GameOver, Win }

Tests : 3.

Important : ajouter une variante oblige à mettre à jour tous les match state dans les 5 jeux.

Ré-exporté par : chaque jeu.

- Shape::Aabb (convention Rust pour acronymes).

Tests : 12.

## games/bullet-hell — Détail (dernier jeu en date)

### Concept

Shmup vertical, 6 vagues hand-authored, hitbox minuscule (2.5 px), focus mode, graze + multiplicateur.

Contrôles : flèches/WASD pour bouger (pas d'inertie), Shift pour focus, Espace pour tirer (maintien), R pour restart.

### Structure

games/bullet-hell/
├── Cargo.toml          # edition + deps via .workspace = true
├── .env                # COLOR_* en {PREFIX}_R/G/B/A
├── waves.ron           # 6 vagues
├── src/
│   ├── main.rs         # boucle, input, match GameState, render
│   ├── lib.rs
│   ├── config.rs       # GameContext
│   ├── components.rs   # Player, Bullet, Enemy, Emitter, EntryMotion, Particle, rand01
│   ├── waves.rs        # WaveData, EnemyData, load_waves, enemy_style, pos_vec
│   └── systems.rs      # World, update, update_*, spawn_wave, resolve_*, reset
└── tests/
    └── game_scenarios.rs   # 11 tests d'intégration

### Détail technique

- Transform.position = centre (déviation documentée).
- Pas de wrap-around : playfield = fenêtre moins HUD strip de 20 px.
- 4 émetteurs : Radial, Aimed, Spiral, Wall (data-driven dans waves.ron).
- 3 entrées : Static, Drift, Sine.
- 3 kinds : grunt, tank, boss.
- Graze : ring de 12 px autour de la hitbox (2.5 px). Multiplicateur 1.0 → 8.0, décroît de 0.5/s, reset à 1.0 sur mort.
- Juice game-local : screen shake, hitstop (80 ms), particles, HP par assombrissement (pas d'anneau/arc).
- World state struct (3e occurrence après MatchState, SnakeWorld).

### Pièges connus

- draw_arc macroquad 0.4.16 : signature est (x, y, segments: u8, start, end, radius, thickness, color). segments en 3e position, radius en 6e. Le compilateur suggère le swap.
- HP indicators dans un shmup : préférer l'assombrissement par hp/max_hp aux anneaux/arcs. L'arc partiel donne un artefact de "trait blanc" à HP quasi-plein.
- Tests de collision : le graze ring est player_graze_radius + bullet_radius depuis le centre du joueur (pas player_graze_radius seul). Idem pour hitbox : player_hitbox_radius + bullet_radius.
