## Vue d'ensemble du projet

Ember est un moteur de jeu 2D en Rust, avec une architecture en 3 couches :

1. ember_core — Primitives pures, aucune dépendance graphique.
2. ember_stdlib — Briques de jeu réutilisables, dépend de macroquad.
3. games/* — Jeux spécifiques, chacun dans son dossier.

Stack technique :
- Langage : Rust, edition 2024 partout.
- Rendu / input / fenêtre : macroquad 0.4 avec feature "audio" activée.
- Math : glam 0.27 (aligné sur macroquad 0.4.16).
- Sérialisation : serde + ron.
- Config : dotenvy (fichiers .env).
- Structure : Cargo workspace avec [workspace.package] (edition, version) et [workspace.dependencies] (versions + chemins internes).
- Resolver : resolver = "3" explicite dans le workspace racine.
- Convention Session 6 : tous les membres utilisent edition.workspace = true, version.workspace = true et dep.workspace = true. [workspace.dependencies] est la source unique de vérité. Bumper une version = éditer un seul fichier (le root). Vérifié par cargo tree -i glam / -i macroquad → une seule version résolue pour tout le workspace.

Conventions clés :
- transform.position = top-left par défaut, sauf :
  - Bullet Hell : position = centre (déviation assumée, documentée dans bullet-hell/src/lib.rs).
- Les jeux sont data-driven via des fichiers .ron.
- Les tests sont obligatoires (unit + intégration).
- La stratégie est "Rule of Three" : on n'extrait dans le moteur qu'après avoir vu le pattern 3 fois.
- Crates externes : tirets dans Cargo.toml (ember-core, bullet-hell), underscores dans le code (ember_core, bullet_hell).
- cargo clippy --workspace --all-targets -- -D warnings est le gate de qualité. Il doit rester vert.
- State structs : chaque jeu expose un unique struct qui possède tout l'état mutable (MatchState, BreakoutWorld, SnakeWorld, GameWorld, World pour Bullet Hell, Game pour Minesweeper, App + GameWorld pour Simon, Game pour Memory, Game pour FreeCell, Game pour Air Hockey, Game pour Zhuo Ji). main.rs tient une seule variable de ce type. C'est une convention, pas un type partagé.
- **Layout uniforme (Phase 14)** : le state struct vit dans `systems.rs`, `GameContext` vit dans `config.rs`, `lib.rs` fait les réexports. `systems.rs` fait `pub use crate::config::GameContext;` pour compat.
- Séparation BoardState / GameState (Minesweeper) : l'état interne du plateau (Ready/Playing/Won/Lost) est distinct de l'état d'écran (Start/Playing/Win/GameOver). Transitions explicites.
- Boutons UI : update() et draw() doivent être appelés sur la MÊME instance. Si le bouton est recréé dans le rendu, l'event de clic est perdu. Conserver les boutons dans le state struct du jeu.
- .env colors : env_color("PREFIX", default) lit quatre variables séparées PREFIX_R, PREFIX_G, PREFIX_B, PREFIX_A, chacune un f32 dans [0.0, 1.0]. Jamais une chaîne r,g,b,a. Préférer le préfixe COLOR_<ROLE>_.
- draw_text vs draw_centered vs Label::new :
  - draw_text(format!(...), ...) — macroquad accepte impl AsRef<str>, donc PAS de &.
  - draw_centered(&format!(...), ...) — signature prend &str, donc le & est nécessaire.
  - Label::new(format!(...), ...) — prend impl Into<String>, donc PAS de &.
  Règle générale : si la fonction prend impl AsRef<str> ou impl Into<String>, retirer le &. Clippy râle (needless_borrows_for_generic_args) sinon.
- TextDimensions : macroquad::draw_text retourne TextDimensions, pas (). Pour ignorer, terminer par ;.
- manual_range_contains : écrire (a..=b).contains(&x) au lieu de x >= a && x <= b.
- **Design docs (Phase 17)** : chaque nouveau jeu doit avoir un `DESIGN.md` dans son dossier. Premier : `games/memory/DESIGN.md`. À faire rétroactivement pour les 8 autres jeux sauf Air Hockey et Zhuo Ji.
- **Clavier AZERTY vs QWERTY (Phase 18)** : macroquad utilise les scancodes QWERTY, pas les caractères du layout. Sur AZERTY : `M` → `KeyCode::Semicolon`, `Z` → `KeyCode::W`, `A` ↔ `Q`, `W` ↔ `Z`. Toujours préférer `Tab`, `Escape`, `Space`, `Enter`, ou les touches de fonction pour les raccourcis critiques. Solution FreeCell : `Tab` pour le menu, `Z`/`W` pour undo (double mapping), `Y` pour redo (position identique).
- **`clippy::collapsible_if` (Phase 21)** : let-chains (`if let Some(x) = ... && cond { }`) stables depuis Rust 1.88, à utiliser.
- **`clippy::doc_overindented_list_items` (Phase 21)** : sous-items doc-comment alignés à 2 espaces après le `-`.
- **`clippy::too_many_arguments` (Phase 21)** : bundler en tuple. Ex : `draw_filter_btn(rect: (f32, f32, f32, f32), ...)`.

## games/zhuo-ji — Détail (11e jeu)

### Concept

Zhuo Ji (捉鸡), la variante Guiyang du Mahjong. 4 joueurs, 108 tuiles
(3 suits × 9 rangs × 4 copies, pas d'honneurs). Deux mécaniques
signatures :

- **豆 (Dou)** — les bonus de Gang, qui servent aussi de "passeport"
  pour gagner sur un discard (règle 平胡 vs 大对子).
- **鸡 (Ji)** — une tuile révélée après la main qui multiplie le score.
  Tuiles fixes : **1 Tiao** (幺鸡) et **8 Tong** (八筒), qui deviennent
  Golden Ji sous certaines conditions.

### Détail technique

- **Wall** : 108 tuiles, `build_wall()` retourne l'ordre canonique,
  `shuffle()` Fisher-Yates via `Rng`. Deal : 13 par joueur, le dealer
  reçoit une 14e dans `drawn` (séparée du `concealed`).
- **Phases** : `Deal → AwaitingDraw → DrawAnim → AiThinking → AwaitingDiscard → AwaitingClaims → ClaimAnim → (loop | Hu | HuangZhuang) → MatchOver`.
- **Claims** : Peng, Gang, Hu. Pas de Chi. Priorité `Hu > Gang = Peng`,
  puis distance counter-clockwise depuis le discarder.
- **Shanten** : `(4 - melds) * 2 - partials - has_pair`. Recherche
  exhaustive avec memo sur `(Vec<Tile>, max_sets)`.
- **`is_winning_hand`** : backtracking sur les paires candidates puis
  partition en melds. Reconnaît aussi les **7 paires** (`is_seven_pairs_hand`).
- **AI** : `decide_discard` minimise le shanten post-discard, tie-break
  sur le moins de voisins (≤2 rangs). `decide_claim` Peng si shanten
  strictement réduit. `decide_an_gang` An Gang si shanten ne régresse
  pas. `decide_ming_gang` : 3 copies en main.
- **Scoring** : `apply_hand_scores` applique pattern fan + Dou +
  Ji pairwise et retourne un `HandBreakdown` (buckets `hu` / `dou` /
  `ji` par joueur, utilisés par le modal fin de main).
  **8 patterns** : PingHu(1), DaDuiZi(5), QiDui(10), QingYiSe(10),
  QingDaDui(15), LongQiDui(20), QingQiDui(20), QingLongBei(30).
  `apply_huangzhuang_scores` : 2 fan par tenpai × non-tenpai.
- **Chong Feng Ji / Ze Ren Ji** : `Game.first_discard: Option<(usize, Tile)>`
  + `record_discard()`. Premier 1 Tiao jeté → bonus doublé au discarder
  (1 ou 2 fan selon golden) ; si ce 1 Tiao est Peng'd → discarder paie
  +1 fan à chacun.
- **Match** : `hands_played` counter, MatchOver après 16 mains.
  **Space** étend de 16, **R** fait un nouveau match.
- **Timers** : 30s turn window pour l'humain (auto-discard), 10s claim
  window, 0.6s AI think, 0.4s claim animation.
- **Seed** : aléatoire depuis `SystemTime::now()`.
- **Tuiles custom** (`tiles.rs`) :
  - **WAN** : petit chiffre rouge en haut à gauche, chiffre noir centré,
    barre rouge + accent sous le chiffre (proxy pour 万).
  - **TIAO** : barres vertes/rouges alternées par position.
    **1 Tiao = poulet stylisé** (corps crème, crête rouge 3 lobes,
    barbillon, bec orange, œil cartoon, 2 pattes, queue 3 plumes) —
    Ji permanent.
  - **TONG** : cercles **bleus** + centrale rouge (position 1,1) ;
    le 1 est un cercle concentrique bleu/blanc/rouge, le 8 est tout
    noir (Ji permanent).
  - **Taille uniforme** 40×54 partout. Hand 56×84, river/AI backs 30×46,
    AI melds 28×42.
  - **`draw_tile_standing_base` + `draw_tile_standing_face`** : split
    pour rendu en 2 passes (fix z-index melds East).
  - **`TileGlow { None, Useful, Ji }`** : halo autour des tuiles utiles
    (vert 0.40, 0.95, 0.55) ou Ji (or 1.00, 0.82, 0.30), priorité
    Ji > Useful. Rendu par deux `draw_rectangle_lines` superposés.
- **Layout UI** : info stack en haut-gauche (shanten, waits, hand, turn,
  phase), WALL pile en haut-droite, pendule pile au centre de l'écran
  (runtime `screen_width() / 2`, `screen_height() / 2`), flèche vers le
  siège actif, avatars 50×50, rivières "en face" de chaque joueur.
  Melds en **3 slots** + 4e tuile de Gang empilée (`MeldsLayout`,
  gap `MELD_INTER_GAP = 12px`).
- **Modals** : fin de main (2 onglets Scores / Table view, nav ← →),
  fin de match (2 onglets Scores / Hand history, titre pulsant),
  menu principal (`AppScreen { Menu, Game }`, écran titre jade,

- **help.rs** : 7 onglets (Goal/Patterns/Dou/Ji/Tiles/Specials/UI),

- **Tests** : **187 unitaires + 10 intégration = 197 tests**.

### Pièges connus (Zhuo Ji)

- **Tile `Copy`** : utiliser `Vec::remove`, pas `swap_remove`, pour
  préserver l'ordre (crucial pour hand evaluation).
- **Claim priority** : Hu > Gang = Peng. Deux joueurs Peng la même
  tuile → le plus proche counter-clockwise du discarder gagne.
- **Pas de Chi.**
- **Gang → re-draw** : après chaque Gang, même joueur pioche à nouveau.
- **Dou passport rule** : sans Dou, on ne peut pas Hu sur discard avec
  seulement 平胡.

- **Huangzhuang ne compte pas Dou/Ji.**

  propager vers `HandBreakdown` (modal fin de main) et `first_discard`
  (Chong Feng Ji). `apply_hand_scores` dans `on_hu` prend 5 args.

- **`measure_text` dans un test** : remplacer par offset calculé
  (`fs * 0.40`).
- **`assert!(CONSTANT > CONSTANT)`** → `const _: () = assert!(...)`.
- **Test "neutre" Zhuo Ji** : vérifier que les tiles neutres ne sont
  pas le primary actif.
- **`f32::min` ambiguïté** : suffixer `56.0_f32` sur le premier élément.

- **Melds largeur** : Peng (3) et Gang (4) doivent occuper la **même

- **Pendule centrée H + V** : la flèche sort du disque — ne pas la
  compter dans le calcul du centrage.

## games/freecell — Détail (9e jeu)

### Concept

FreeCell, le solitaire à information parfaite (1978, Paul Alfille). Un
jeu de 52 cartes, toutes visibles dès le départ. Pas de pioche, pas de
hasard pendant la partie. Le joueur déplace des cartes entre 8 colonnes
du tableau, 4 cellules libres (en haut à gauche), et 4 fondations
(en haut à droite).

Objectif : déplacer toutes les cartes vers les fondations, par couleur
et dans l'ordre croissant (A → 2 → ... → K).

Thème visuel : terminal dev (fond sombre, symboles Unicode ♠ ♥ ♦ ♣).

### Détail technique

- **Cartes** : `Card { suit: Suit, rank: Rank }`, `Rank(pub u8)` avec 1=As, 11=Valet, 12=Dame, 13=Roi.
- **Zones** : `Zone::Column(0..8)`, `Zone::FreeCell(0..4)`, `Zone::Foundation(0..4)`.
- **Distribution** : 4 colonnes de 7 + 4 colonnes de 6 = 52. Déterministe via `Rng` + Fisher-Yates.
- **Règles** : `can_place_on_column`, `can_place_on_foundation`, `can_place_in_cell`, `max_super_move`.
- **Super-move** : `(1 + cellules_libres) × 2^colonnes_vides`. **Piège** : colonne vide de destination ne compte pas comme buffer.
- **Accessibilité** : run contigu du bas seulement. `is_accessible(from, start_idx, n)` vérifie `start_idx + n == columns[col].len()`.
- **Drag-and-drop** : `DragState::Idle / Pressing / Dragging`. Seuil de 5 px.
- **Undo/redo** : snapshots complets. Pile `history` / `future`.
- **Hint** : `find_hint()` retourne `Hint { from, to, card }`. Priorité : fondation > colonne > cellule libre.
- **Best time** : `Persistence<HashMap<String, f32>>`, clé = seed stringifiée.
- **Police** : DejaVu Sans Mono pour ♠ ♥ ♦ ♣.
- **Raccourcis** : `N` new, `R` restart, `Tab` menu, `Z`/`W` undo, `Y` redo, `Escape` quit.
- **Tests** : **81 unit + 8 integration = 89 tests**.

## games/air-hockey — Détail (10e jeu)

### Concept

Air Hockey, arcade 2 joueurs (ou 1 joueur vs IA). Table horizontale,
deux palets contrôlés par W/A/S/D (J1) et flèches (J2), un palet
unique. Objectif : 3 buts par manche, 2 manches gagnantes sur 3.

### Détail technique

- **Phases** : Menu → Countdown → Playing → GoalPause → (Countdown | RoundOver | MatchOver).
- **Physique** : `step_world_substepped` avec `substeps = 4`. Palet clampé à `puck_speed_max = 1400`.
- **Hitstop** : `dt_eff = 0.0` quand palet tape palet à plus de 900 px/s. **Ne pas** appeler `step_world_substepped` quand `dt_eff == 0.0`.
- **IA goalkeeper** : `REACTION_TIME = 0.18s`, `AI_SPEED = 0.55`, `GOALIE_OFFSET = 70.0`. Ne chasse jamais en x.
- **Menu** : Space = PvP, Enter = PvAI.
- **Countdown** : `TextParams { font_size: 120, font_scale: 1.4→1.0 }`. Ne JAMAIS animer `font_size`.
- **Overlays** : scrim noir alpha 0.55.
- **Tests** : **58 unit + 10 integration = 68 tests**.
